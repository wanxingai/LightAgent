## 持续研究缺口修复与最终评估（2026-10-05）

**评估结论：P0–P4 作为单机开发者基础框架，功能开发及约定的小规模验收已完成，可进入发布候选阶段；尚不能称为已正式发布或已通过长期生产运行验证。** 本次复核确认的四项缺口已修复：

| 缺口 | 修复及验证 |
| --- | --- |
| 研究轮次只能看到摘要，无法复用旧脚本与证据 | 把同研究员、同评估序列的合格成果复制进冻结输入，提供来源索引、预算、哈希校验、完整历史关键词检索和显式选择；测试第二轮真实读取并执行前轮脚本，候选与基线共享冻结输入，篡改、跨归属与超预算被拒绝 |
| 长指令达到上下文上限后没有恢复路径 | 新增宿主审阅、指纹校验、不可变替代指令和原回执保留；测试阻塞→暂停归档→重启继续。新消息按可容纳的连续部分领取，测试两条各 64 KiB 消息逐步应用，不能容纳时不消费执行预算 |
| 超过 1000 条的旧实验及成果无法正常访问 | 新增稳定游标分页、完整历史搜索、按 ID 查询和完整账本成果授权；面板提供搜索、加载更早实验和旧成果预览，保持原列表 API 的兼容性 |
| SQLite 锁竞争使 Job 监控线程退出 | BUSY/LOCKED 有界退避；控制状态持续不可用时取消受管进程组；终态写入失败保留受保护的恢复凭据，通过 OS 锁和 nonce 核对后恢复，不重放命令。包含真实子进程、数据库竞争与无效凭据测试 |

跨轮成果选择在发布前验证；另提供暂停且空闲时的 `clear_reuse_request()`，用于恢复旧报告或输入增长造成的无效/过大请求，保留原始证据。指令归档及成果请求清除均有面板入口。

## 后续实现与新版面板验收（2026-10-04）

最终完整回归：**534 passed、3 skipped，93.51 秒**。范围为已跟踪测试、全部新增 `test_v012_*.py` 和按配置跳过的 Codex 集成入口；未收集仓库内无关旧草稿。此前与其他验收并行的运行有 533 项通过、1 项旧 DAG 子进程启动超时、3 项跳过；该项独立重跑 2.44 秒通过，未改动其恢复断言或超时值，随后上述串行全量运行通过。小规模测试验证功能与恢复机制，不替代长期运行和生产负载测试。

本轮补齐以下开发缺口：

- 候选显式重评保留原版本、输入、提示、基线与失败记录；消费新轮次/调用预算，重启后先核对再继续。新到的研究要求进入后续正常轮次。
- steering 领取与迟到 ACK 重新检查轮次、attempt、turn 和 epoch，不覆盖已失败、取消或核对的应用回执。
- 可信适配器显式声明的安全暂时性错误可有界退避；不重试未知副作用。Job 在事务内预留全局/研究员并发槽，未知任务继续占槽并支持显式结算。
- runner 运行时轮转日志；终态工作副本支持默认预览的清理，保留哈希成果、冻结输入与未核对工作。聊天失败诊断及事件脱敏。
- 新版本冻结执行配置、工作流/上下文摘要，以及可变脚本的内容或缺失状态。初始不存在的脚本后来加入项目，不会进入旧版本；候选明确创建才解除缺失约束。
- 评估契约提案必须经宿主在暂停且空闲时批准，开启新的比较序列和基线，保留预算。契约 A→B→A 后仍禁止跨序列回滚。旧版本内容 ID、无执行配置/无比较序列记录保持兼容。

真实浏览器连接本机 fixture 服务，验证中文导航、实验卡、文本证据弹窗、独立聊天收到回复、追加方向回执变为 applied、暂停与恢复、评估契约采用后新基线发布、工作区清理预览。契约切换后实验数由 4 增至 5，已消耗轮次由 9 增至 10，未重置预算。390 px 窄屏的文档与视口宽度均为 390 px，未出现横向溢出；最终浏览器错误日志为空。预览数据明确标注“本地演示”，未用它证明研究效果；验收后关闭临时服务。


真实 Codex 持续研究另行重跑：**1 passed，144.22 秒**。完成三行本地数据计算、消息应用、独立聊天及服务重启后的第二次发布。这个场景使用已登录的本机 CLI；原生路径的独立 runner 和协议 fixture 纳入离线回归。实验性 App Server 的真实模型 steering 本轮仍未验证。

## 高优先级复核修复（2026-10-04）

上一轮针对复核发现的五项高优先级问题修复；后续开发结果见本文开头新增验收记录：

- Inbox、聊天和恢复调度改为按状态过滤的 keyset 分页；超过 1000 条较新聊天记录后，旧消息仍被领取，已应用的人类约束仍进入研究上下文。
- 正常停止服务等待已领取任务收尾，保留目标的 running 意图；验证停止期间状态为 stopping、消息正常应用、重启无需 resume 即完成下一轮，预算延续。
- Job 完成通知遇到记录/存储限额时保持待投递状态，持久化退避时间；其他研究员继续运行，释放容量后只投递一次。
- 受管文件分配使用共享数据库锁检查容量；覆盖快照、候选、DAG/成果、聊天和 Job 输出。两个独立进程竞争剩余容量时仅一个写入成功；小预算阻止多次快照复制后继续发布；执行器超写会收到取消，超额实验不发布。外部进程仍可能瞬间超写，这是协作式预算而非 OS 硬配额。后续新增契约/版本元数据后，此 fixture 预算从 256 KiB 调为 384 KiB，并加强首份快照完整落盘、后续复制受限且零模型调用的断言。
- submit/run 创建支持幂等键；8 次并发重试只创建一个研究员。启动失败抛出包含句柄、根目录和请求 ID 的 ServiceStartupError，配置变化复用旧键被拒绝。

新增 11 项回归测试。本轮完整回归 **463 passed、3 skipped（80.62 秒）**；在随后补充 Job 存储场景并完成最终容量检查后，持续研究测试单独重跑 **33 passed（21.02 秒）**。这两组数量有重叠，不相加。外部模型集成测试仍按配置跳过，本轮没有重新调用真实模型。更新后的 wheel 构建及仓库外安装导入通过。

## 未宣称的保证

没有执行 24 小时/多日 soak、跨机器故障恢复、云部署、生产压力测试或真实金融回测。外部副作用没有 exactly-once 保证。原生宿主 Provider 不隔离恶意候选，Codex 读取边界也不能用于保护同机秘密标签。默认 evidence 评估只检查证据完整性；应用必须提供适合领域的独立验证器与评估器。

服务会遵守预算并在容量不足、认证/验证失败或未知结果时等待或阻塞，而不是为“持续研究”绕过限制。标准 runner 日志已支持运行时轮转，已核对的终态工作副本可显式清理；冻结输入、恢复记录和长期归档仍需部署方规划。模板只提供托管方式，不会安装系统服务。
