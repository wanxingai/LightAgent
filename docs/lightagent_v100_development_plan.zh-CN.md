# LightAgent v1.0.0 开发规划

主题：通用执行内核收敛与边界稳定化。

- 更新日期：2026-11-09。
- 状态：原 v0.13.0 开发范围转为 v1.0.0，尚未发布。拆分、历史迁移、Worker/Docker、本地多 Python 矩阵和持续负载的历史结果对应各自测试快照，不代表当前提交的远端 CI 或部署验收已通过。
- 实现基线：LightAgent v0.12.0 本地开发代码及现有验收记录。
- 跨项目职责见下文；目标架构不表示所有适配或正式发布验收已完成。

下一版不应继续把研究功能、用户界面和执行机制都集中到 LightAgent，而应在 v0.12.0 基础上做职责拆分，同时保留原路线图中的恢复与安全加固工作。

## 一、版本目标

- **LightAgent**：提供唯一的通用执行、状态、消息、预算和恢复机制。
- **LightResearch**：承接实验、评估、成果积累和研究员版本改进。
- **LightWorker**：提供统一聊天、审批、工具环境和正式用户界面。

这里的“唯一权威”不要求所有数据合并进同一个数据库，而是避免多个项目分别决定任务状态、领取消息或重试执行。

## 二、删减与迁出

| v0.12.0 中的内容 | v1.0.0 处理方式 | 目标归属 |
| --- | --- | --- |
| ResearchContract、研究提示词、假设与实验循环 | 从执行核心抽离，作为领域扩展 | LightResearch |
| ResearchEvaluator、PromotionPolicy、研究指标与比较序列 | 迁出领域实现；保留通用 Verifier 接口 | LightResearch |
| 研究员 AgentVersion、候选晋升、谱系和回滚 | 迁出研究版本管理；执行配置摘要及完整性基础仍保留 | LightResearch / LightAgent |
| 跨轮实验成果选择、研究历史复用策略 | 核心只保留工件、来源和检索接口，研究层决定如何选取 | LightResearch |
| ResearchPanel | 不再作为核心产品界面扩展；保留研究调试示例 | LightResearch；正式界面归 Worker |
| AgentService、ResearchStore | 拆分通用服务机制与研究领域状态，不能整目录搬迁 | 分层保留 |
| Docker、浏览器、Office、默认工具包与业务模板 | 不加入核心强制依赖，由宿主配置具体实现 | LightWorker / 可选扩展 |
| Worker 中重复的 Job、Inbox、预算与生命周期逻辑 | 框架补齐并验收后，逐步改为适配层 | LightAgent |

这些是**移除职责重复和默认耦合**，不是删除已有能力、历史记录或恢复证据。

## 三、必须保留

普通 `run()`、`arun()`、流式输出、Tools、Hooks、Guardrails、Memory、LightSwarm、LightFlow、LightDAG，以及 SecurityContext、CapabilityGate、审批和工件契约继续保留。

原生和 Codex 后端保持可选，不把 Codex 或宿主 Shell 变成默认依赖。

## 四、重点增加

| 优先级 | 工作项 | 交付内容与边界 |
| --- | --- | --- |
| P0 | 通用持久执行服务 | 普通任务也能提交、重连、暂停、取消和恢复，不再必须携带研究契约、Evaluator 或研究员版本。 |
| P0 | 原子状态与消息契约 | 收敛事务追加、CAS、幂等键、Inbox 领取和回执；吸收 Worker 的通用存储加固，避免陈旧保存覆盖新事件。 |
| P0 | 统一 Job 与子 Agent 生命周期 | 统一 owner、attempt、epoch、租约、输出游标及父子取消；连续子会话通过公开接口恢复，未知副作用不自动重放。 |
| P0 | 统一预算账本 | 预留、扣减和结算具有幂等性；研究额度与用户预算共用执行核算，不重复扣减，也不通过子任务绕过限制。未知费用明确标记。 |
| P0 | 宿主执行边界 | 后端能力探测与权限映射可验证；Worker 要求 Docker-only 时，能力缺失必须拒绝执行，不能回退宿主 Shell。 |
| P1 | 统一交互请求协议 | 标准化追问、计划审阅和操作审批的请求、响应、过期及取消；核心管关联与校验，Worker 决定弹窗和产品审批策略。 |
| P1 | 通用唤醒与事件接口 | 提供持久触发、去重、领取、错过触发的处理策略及恢复；研究间隔由 Research 定义，用户计划编辑与通知由 Worker 提供。 |
| P1 | 版本化公开契约与安全验证 | 明确事件/schema、能力矩阵、错误和迁移契约；补会话完整性、扩展摘要变化重授信、恶意输入及资源竞争测试。 |

不再新增另一套调度器；这些能力应从现有实现中收敛、补齐并公开。

## 五、兼容与迁移

1. 冻结 v0.12.0 源码、构建产物和验收基线，保留历史状态样本。
2. 先提取通用机制，再让现有研究实现通过这些接口运行。
3. LightResearch 是同级的独立源码目录，版本号独立。默认 CI 只验收核心；[联合验收](clean_environment_acceptance.zh-CN.md)显式指定扩展源码或 wheel。
4. Worker 按模块迁移；新适配通过验收后，才停止旧实现的状态决策。
5. 核心不反向导入 LightResearch。旧研究入口通过明确的兼容/扩展注册方案过渡；不能把原 `mode="persistent"` 静默改成另一种语义。

## 六、发布验收

- 未安装 LightResearch、LightWorker、Docker、Codex 时，核心导入和普通任务仍正常。
- 普通任务与研究任务使用同一套执行控制契约；UI 不直接修改框架内部表。
- 并发领取、重复请求、服务崩溃、陈旧 epoch、迟到审批和预算竞争测试通过。
- Worker 的 Docker-only、精确参数审批、父取消和冷恢复完成真实集成验证；缺失环境不能计为通过。
- 历史 Session、Job、消息回执、成果与研究账本具备迁移校验和回退步骤，不重写旧摘要绕过检查。
- Python 3.10–3.13 CI、隔离 wheel 安装及持续运行验收通过；运行时长和负载如实记录。

## 七、本版暂不增加

完整 IDE/PR 工作台、插件市场 UI、Office 套件、浏览器产品、金融数据包、分布式执行和更多递归研究算法，都不作为 LightAgent v1.0.0 的核心交付。

**下一版的核心取舍：研究业务和产品界面做减法，通用执行正确性、宿主安全边界和跨项目集成契约做加法。**

## 八、实施进度（2026-11-09）

- [x] 冻结 v0.12.0 源码快照与 wheel；不覆盖原 dist 或历史账本。
- [x] 研究契约、Evaluator、PromotionPolicy、AgentVersion、成果选择与研究面板迁至同工程的可选 LightResearch 包，独立版本 `0.1.0.dev0`。
- [x] 研究面板、示例、服务模板及测试同步迁移；核心 runner 移除面板选项，旧入口通过显式兼容注册过渡。
- [x] 新增普通 ExecutionService/ExecutionHandle，不要求研究契约；与研究扩展共享 supervisor 生命周期、ControlStore、Job 机制和预算账本。
- [x] SQLite Session 追加、跨实例事务、CAS、幂等校验、新会话哈希链；旧会话不静默重算摘要。
- [x] 持久预算预留/结算、祖先账户额度、未知费用状态；缺少后端硬限额能力时拒绝声称支持费用/token 硬限制。
- [x] 通用交互与唤醒协议初稿：精确批准、过期、陈旧 epoch、重复消费、skip/coalesce 与事务去重。
- [x] 后端探测声明隔离与预算能力；Docker-only 不能回退宿主或 Codex sandbox。
- [x] Runtime Job/外部 Job 共用状态转换、attempt/epoch 和公开投影；Subagent 的执行、并发和取消收敛到 Job，删除旧独立状态机，冷重连需宿主显式绑定。
- [x] 用冻结 v0.12.0 wheel 实际生成 Session/Job/消息/实验/产物历史，完成离线备份、副本加锚与恢复、旧 wheel 回退读取演练；旧摘要不改写，未知效果不重放。
- [x] Worker 可选 DockerWorkspaceProvider 适配，真实容器验证 Docker-only、精确审批与防重放、父取消后容器退出、独立进程中的连续子会话冷恢复；模型响应为 fixture，不是实际 LLM 调用。
- [x] 定义并通过 Skill/MCP/Provider 的签名、发布者信任、持久撤销、配置/内容变化重授信、降级、路径竞争与资源耗尽矩阵；严格模式接入 Worker 能力组合层。
- [ ] 生产规模历史数据与部署方远端 MCP 身份/真实服务矩阵；签名不证明远端内部代码，当前可选适配也不等于默认 Worker 全量切换。
- [x] 本地 Python 3.10–3.13 官方镜像干净矩阵：各 770 passed、8 个明确的 opt-in 跳过，pip check、核心/研究独立 wheel 和单独 HEAD 39 项测试通过；不继承宿主包，测试容器断网。
